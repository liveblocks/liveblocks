Storage is the persistent document inside Sync. Its conflict-free data types
describe how concurrent edits should combine.

<Banner title="Start with your document shape">

Define the smallest shared document that represents the collaborative artifact.
Keep temporary user state such as cursors and selections in
[Presence](/docs/products/sync/presence).

</Banner>

## Choose a data type [#choose-a-data-type]

| Data type                   | Use it for                            | Similar JavaScript value |
| --------------------------- | ------------------------------------- | ------------------------ |
| [`LiveObject`](#liveobject) | Records with named properties         | Object                   |
| [`LiveList`](#livelist)     | Ordered collaborative collections     | Array                    |
| [`LiveMap`](#livemap)       | Collections keyed by IDs              | Map                      |
| [`LiveText`](#livetext)     | Plain or formatted collaborative text | String                   |
| [`LiveFile`](#livefile)     | References to uploaded binary files   | File reference           |

## LiveObject [#liveobject]

Use [`LiveObject`](/docs/api-reference/liveblocks-client#LiveObject) for records
whose properties can change independently.

```ts
import { LiveObject } from "@liveblocks/client";

const shape = new LiveObject({
  type: "rectangle",
  x: 100,
  y: 80,
});

shape.update({ x: 120, y: 90 });
```

Updating `x` does not overwrite a concurrent update to `y`.

## LiveList [#livelist]

Use [`LiveList`](/docs/api-reference/liveblocks-client#LiveList) when order is
part of the shared state, such as layers, columns, or steps.

```ts
import { LiveList } from "@liveblocks/client";

const layers = new LiveList(["background", "content"]);
layers.push("annotations");
layers.move(2, 1);
```

Concurrent insertions and moves are merged into one consistent order.

## LiveMap [#livemap]

Use [`LiveMap`](/docs/api-reference/liveblocks-client#LiveMap) for entities
addressed by stable IDs, such as shapes, nodes, cells, or records.

```ts
import { LiveMap, LiveObject } from "@liveblocks/client";

const nodes = new LiveMap([
  ["node-1", new LiveObject({ x: 0, y: 0, label: "Start" })],
]);

nodes.set("node-2", new LiveObject({ x: 160, y: 0, label: "Finish" }));
```

## LiveText [#livetext]

Use [`LiveText`](/docs/api-reference/liveblocks-client#LiveText) for
collaborative plain text or rich text with inline attributes. It is the
recommended Storage type for new text-editor integrations.

```ts
import { LiveText } from "@liveblocks/client";

const title = new LiveText("Project plan");

title.insert(title.length, " draft");
title.format(0, 7, { bold: true });
```

LiveText can power different editors through Liveblocks integrations. See the
[Text editor use case](/docs/use-cases/text-editor) and
[Sync integrations](/docs/products/sync/integrations).

## LiveFile [#livefile]

Do not store binary data directly in `LiveObject`, `LiveList`, or `LiveMap`. Use
[`LiveFile`](/docs/api-reference/liveblocks-client#LiveFile) to keep a reference
in Storage while the uploaded file is managed separately.

## Nest data types [#nest-data-types]

Live structures can contain JSON-compatible values and other live structures.
Model entities so independently edited values live in independently editable
properties.

```ts
import { LiveList, LiveMap, LiveObject, LiveText } from "@liveblocks/client";

const document = new LiveObject({
  title: new LiveText("Untitled"),
  pages: new LiveList([
    new LiveObject({
      id: "page-1",
      shapes: new LiveMap(),
    }),
  ]),
});
```

Read [`Storage`](/docs/api-reference/liveblocks-client#Storage) for supported
values, methods, and serialization behavior.

## Read immutable snapshots [#immutable-snapshots]

Storage selectors return immutable snapshots for rendering. Read values from
these snapshots, and make changes inside `useMutation` through the mutable
Storage structures provided to the callback.

```tsx
import { LiveObject } from "@liveblocks/client";
import { useMutation, useStorage } from "@liveblocks/react/suspense";

const shapes = useStorage((root) => root.shapes);

const addShape = useMutation(({ storage }, id: string) => {
  storage.get("shapes").set(id, new LiveObject({ x: 0, y: 0 }));
}, []);
```

JSON-compatible leaf values include strings, numbers, booleans, `null`, arrays,
and objects. Use a live data type at boundaries where collaborators need
independent edits to merge.

## Type your document [#type-your-document]

Declare the global `Liveblocks.Storage` interface so selectors, mutations, and
server integrations share the same document type.

```ts file="liveblocks.config.ts"
import type { LiveMap, LiveObject } from "@liveblocks/client";

declare global {
  interface Liveblocks {
    Storage: {
      shapes: LiveMap<string, LiveObject<{ x: number; y: number }>>;
    };
  }
}

export {};
```

See [Typing Storage](/docs/api-reference/liveblocks-react#typing-storage) for
the complete setup.
