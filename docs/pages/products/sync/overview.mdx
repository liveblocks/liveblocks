Liveblocks Sync is a hosted sync engine for building collaborative applications.
Use it to create multiplayer documents, human and agent presence, collaborative
editors, streaming chats, realtime canvases, flowcharts, spreadsheets, and
tables.

<Banner title="Get started with Sync" type="info">

Choose a [get-started guide](/docs/get-started) for your framework or
application, then return here for the underlying concepts.

</Banner>

## Features [#features]

- **Multiplayer collaboration**: Update the same document from multiple clients.
- **Conflict-free data types**: Preserve simultaneous edits without manually
  merging responses.
- **Realtime presence**: Render cursors, avatar stacks, selections, and agent
  activity.
- **Feeds**: Persist streaming chats, agent state, activity streams, and
  workflow messages.
- **Optimistic updates**: Apply changes locally, then synchronize them in the
  background.
- **Server-side editing**: Read and update collaborative documents from a
  trusted backend.
- **Multiplayer undo/redo**: Give each user a history that respects other
  people’s edits.
- **Version history**: Preview and restore meaningful document snapshots.
- **Authentication and permissions**: Control who can read or edit each room.
- **TypeScript-first data**: Type Storage, presence, events, and user info.

## What is a sync engine? [#what-is-a-sync-engine]

A sync engine keeps shared state consistent across connected clients. Instead of
creating an endpoint for every edit, wiring up WebSockets, and reconciling
responses yourself, you update a shared document as if it were local state. Sync
distributes the change, resolves concurrent edits, persists the result, and
catches clients up when they reconnect.

This avoids stale documents, lost updates, and race conditions when several
humans, agents, devices, or tabs can edit the same state.

## When to use Sync [#when-to-use-sync]

Sync is useful when two or more actors can change the same artifact:

- Documents, canvases, code editors, flowcharts, spreadsheets, and tables
- AI agents working in the same document as humans
- Multiple agents editing one shared source of truth
- Chat, activity, and workflow messages that belong with a collaborative room
- Live cursors, avatar stacks, selections, and typing indicators
- Interfaces that must respond before a network round trip completes
- State shared across a user’s devices or browser tabs

If data is only edited by one actor and does not need to be live, a conventional
request/response API may be simpler.

## How Sync works [#how-sync-works]

Your application connects to hosted Liveblocks rooms. Each room is a
collaborative space, usually representing one document, board, issue, or
project. Clients read and update the room’s Storage document while Liveblocks
handles synchronization, persistence, and conflict resolution.

```tsx title="Room.tsx"
"use client";

import { LiveblocksProvider, RoomProvider } from "@liveblocks/react/suspense";

export function Room({ children }: { children: React.ReactNode }) {
  return (
    <LiveblocksProvider authEndpoint="/api/liveblocks-auth">
      <RoomProvider id="my-room" initialStorage={{ count: 0 }}>
        {children}
      </RoomProvider>
    </LiveblocksProvider>
  );
}
```

For prototypes or public rooms, you can use a public API key. For production
applications, [authenticate users](/docs/authentication) and set room
permissions from your server.

### Read and update shared state [#read-and-update-shared-state]

Read Storage with
[`useStorage`](/docs/api-reference/liveblocks-react#useStorage) and modify it
with [`useMutation`](/docs/api-reference/liveblocks-react#useMutation).

```tsx title="Counter.tsx"
"use client";

import { useMutation, useStorage } from "@liveblocks/react/suspense";

export function Counter() {
  const count = useStorage((root) => root.count);

  const increment = useMutation(({ storage }) => {
    storage.set("count", storage.get("count") + 1);
  }, []);

  return <button onClick={increment}>Count: {count}</button>;
}
```

The update appears locally first. Sync sends it to Liveblocks, reconciles it
with concurrent changes, persists it, and distributes the result to the other
clients.

## Storage and data types [#storage-and-data-types]

Storage is the persistent data model inside Sync. Build its document tree from
conflict-free data types:

- [`LiveObject`](/docs/api-reference/liveblocks-client#LiveObject): A record of
  named values
- [`LiveList`](/docs/api-reference/liveblocks-client#LiveList): An ordered
  collection
- [`LiveMap`](/docs/api-reference/liveblocks-client#LiveMap): A key-value
  collection with dynamic keys
- [`LiveText`](/docs/api-reference/liveblocks-client#LiveText): Collaborative
  rich text
- [`LiveFile`](/docs/api-reference/liveblocks-client#LiveFile): A reference to a
  file managed outside the document tree

Read [Data types](/docs/products/sync/data-types) for selection and modeling
guidance.

## Presence [#presence]

Presence is temporary state associated with a connected user or agent. Use it
for cursor positions, selections, typing indicators, active tools, and other
information that should disappear when the connection ends.

```tsx title="Cursors.tsx"
import { useOthers, useUpdateMyPresence } from "@liveblocks/react/suspense";

export function Cursors() {
  const others = useOthers();
  const updateMyPresence = useUpdateMyPresence();

  return (
    <div
      onPointerMove={(event) =>
        updateMyPresence({
          cursor: { x: event.clientX, y: event.clientY },
        })
      }
    >
      {others.map(({ connectionId, presence }) => (
        <Cursor key={connectionId} position={presence.cursor} />
      ))}
    </div>
  );
}
```

Learn which values belong in [presence](/docs/products/sync/presence) and which
belong in Storage.

## Optimistic updates [#optimistic-updates]

Sync applies local mutations immediately and synchronizes them in the
background. This gives collaborative interfaces the responsiveness of local
state while preserving a shared source of truth. Use
[`useSyncStatus`](/docs/api-reference/liveblocks-react#useSyncStatus) when the
UI needs to indicate that changes are still synchronizing.

## Where data lives [#where-data-lives]

Liveblocks hosts, persists, and scales each room’s collaborative data. Use the
dashboard and server APIs to manage rooms, inspect usage, create versions, and
integrate webhooks without operating sync infrastructure yourself.
