`useFeeds` and `useFeedMessages` load up to 50 items by default. Both hooks
return the same pagination controls, so interfaces can load older data without
replacing the items already rendered.

```tsx title="PaginatedMessages.tsx"
import { useFeedMessages } from "@liveblocks/react/suspense";

export function PaginatedMessages({ feedId }: { feedId: string }) {
  const { messages, fetchMore, hasFetchedAll, isFetchingMore, fetchMoreError } =
    useFeedMessages(feedId, { limit: 20 });

  return (
    <>
      {messages.map((message) => (
        <p key={message.id}>{message.data.content}</p>
      ))}
      {!hasFetchedAll && (
        <button disabled={isFetchingMore} onClick={fetchMore}>
          {isFetchingMore ? "Loading…" : "Load earlier messages"}
        </button>
      )}
      {fetchMoreError && <p>Earlier messages could not be loaded.</p>}
    </>
  );
}
```

## Pagination values [#pagination-values]

- `fetchMore` requests the next page and is safe to call repeatedly.
- `hasFetchedAll` is `true` after the final page has loaded.
- `isFetchingMore` prevents duplicate UI actions while a request is running.
- `fetchMoreError` reports errors from later pages separately from the initial
  request.

Use the same pattern with
[`useFeeds`](/docs/api-reference/liveblocks-react#useFeeds) to paginate a room’s
feed list. The `limit` option controls the page size, not the total number of
items the hook can return.

## Infinite scrolling [#infinite-scrolling]

Call `fetchMore` from an intersection observer when the user reaches the
boundary of the list. Guard the call with `!hasFetchedAll && !isFetchingMore`,
and preserve the user’s scroll position when older messages are inserted.
