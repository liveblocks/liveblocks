A chat interface is one feed whose messages contain the information needed to
render each turn. Feeds handles persistence, realtime updates, pagination, and
client/server access; your application defines the message schema and UI.

<Banner title="Build the starting point" type="info">

The [Next.js Feeds get-started guide](/docs/get-started/nextjs-feeds) creates a
working chat-style interface.

</Banner>

## Render messages [#render-messages]

[`useFeedMessages`](/docs/api-reference/liveblocks-react#useFeedMessages)
subscribes to one feed and updates when a message is added.

```tsx title="Chat.tsx"
import {
  useCreateFeedMessage,
  useFeedMessages,
} from "@liveblocks/react/suspense";

export function Chat({ feedId }: { feedId: string }) {
  const { messages } = useFeedMessages(feedId);
  const createMessage = useCreateFeedMessage();

  return (
    <div>
      {messages.map((message) => (
        <article key={message.id} data-role={message.data.role}>
          {message.data.content}
        </article>
      ))}
      <button
        onClick={() =>
          createMessage(feedId, {
            role: "user",
            content: "What changed?",
          })
        }
      >
        Send
      </button>
    </div>
  );
}
```

Use the non-Suspense hook when the interface needs explicit initial loading and
error states. For long conversations, expose a “Load earlier messages” control
using the hook’s [pagination values](/docs/products/feeds/pagination).

## Add an assistant or agent [#add-an-assistant]

Send the user’s message from the client, start the workflow on your server, and
append the result with
[`Liveblocks.createFeedMessage`](/docs/api-reference/liveblocks-node#post-rooms-roomId-feeds-feedId-messages).
Connected clients receive the new message automatically.

```ts title="run-assistant.ts"
const answer = await runAssistant(input);

await liveblocks.createFeedMessage({
  roomId,
  feedId,
  data: {
    role: "assistant",
    content: answer,
  },
});
```

Use a stable message ID when a workflow may retry. If the workflow produces
several kinds of output, include a discriminating field such as `type` and
render each type with its own component.

## Add collaborative context [#add-collaborative-context]

Combine Feeds with:

- [Sync](/docs/products/sync) for the document an assistant reads or edits
- [Presence](/docs/products/sync/presence) for live agent status
- [Comments](/docs/products/comments) for discussions attached to content
- [Notifications](/docs/products/notifications) for updates users should see
  outside the open room

Read [AI Collaboration](/docs/use-cases/ai-collaboration) for an end-to-end
product view.
