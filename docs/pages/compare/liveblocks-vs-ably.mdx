Choose Liveblocks for shared documents and the comments, review, and notification
workflows around them. Choose Ably when its messaging, shared-state, presence,
or chat products match your realtime architecture. Both provide more than message
delivery. [Liveblocks docs](/docs/products/sync) ·
[Ably products](https://ably.com/docs)

This guide compares specific products: Liveblocks Sync, Comments, and
Notifications with Ably Pub/Sub, Spaces, LiveObjects, Chat, and AI Transport.
Ably LiveObjects provides persistent shared maps and counters; the distinction
is which editing model and surrounding experience fit your application.
[LiveObjects](https://ably.com/docs/products/liveobjects)

## Compare the building blocks [#compare-the-building-blocks]

| Area | Liveblocks | Ably |
| --- | --- | --- |
| Shared state | [Storage](/docs/products/sync/storage) documents with objects, maps, lists, and text | [LiveObjects](https://ably.com/docs/products/liveobjects) with shared maps and counters |
| Presence | [Presence](/docs/products/sync/presence) for participant state | Presence and Spaces for shared activity |
| Document editing | [LiveText](/docs/products/sync/storage#LiveText) and supported Yjs integrations | `LiveMap` and `LiveCounter` are shared-state primitives; text editing needs a compatible editing model alongside them |
| Product surface | Shared documents, contextual comments, and notifications | Pub/Sub for messaging, LiveObjects for shared state, Spaces for collaborative activity, and Chat for conversations |
| Interface customization | Default comment components, primitives, and hooks | Product-specific SDKs and components, including a React Chat UI Kit |
| Persistence | Sync data persists until explicitly deleted | LiveObjects expires after its configured inactivity period, 90 days by default |

Sources: [Storage](/docs/products/sync/storage),

## Choose the interface and the infrastructure together [#choose-the-interface-and-the-infrastructure-together]

For a design-review feature, users might annotate an object, mention a teammate,
resolve a thread, and return through a notification. That workflow needs shared
canvas data, contextual discussions, and notifications.

With Liveblocks Comments, you can style the default components or combine hooks
and primitives for a custom interface. This lets you choose how much of the
commenting UI to assemble. Ably also provides ready-made UI for specific use
cases, including its React Chat UI Kit. Choose the components that support the
conversation in your app: a discussion attached to a document, a group chat, or
both. [Liveblocks commenting interfaces](/docs/products/comments/default-components)
· [Ably Chat](https://ably.com/docs/products/chat)

## How do Liveblocks documents compare with Ably LiveObjects? [#how-do-liveblocks-documents-compare-with-ably-liveobjects]

Liveblocks [Storage](/docs/products/sync/storage) includes objects, maps, ordered
lists, and text. Ably [LiveObjects](https://ably.com/docs/products/liveobjects)
supplies shared maps and counters. Both synchronize persistent shared state; the
useful distinction is the operations your feature needs.
[Liveblocks Storage](/docs/products/sync/storage) ·
[Ably LiveObjects](https://ably.com/docs/products/liveobjects)

| Feature in a review app | Liveblocks design | Ably design |
| --- | --- | --- |
| Votes on a proposal | Store shared values in the document | A `LiveCounter` represents a shared count |
| Ordered agenda with editable paragraphs | `LiveList` and a supported text integration | Define ordering and choose the text-editing layer around the shared objects |
| Conversation attached to a shape | Contextual Comments, with application-supplied context | Select Chat or application conversation logic for the required attachment model |

Ably fits applications built around messages and shared objects. Liveblocks fits
applications built around shared documents and their review workflows.

## What happens when a document is inactive or a client reconnects? [#what-happens-when-a-document-is-inactive-or-a-client-reconnects]

Liveblocks stores Sync data until it is explicitly deleted. Ably LiveObjects has
a configurable inactivity retention period from 24 hours to 90 days, with 90 days
the default; longer retention requires discussion with Ably. A document that
must remain untouched for a year needs a retention or archive design that covers
that lifecycle. [Liveblocks retention](/docs/platform/data-storage) ·
[Ably object storage](https://ably.com/docs/products/liveobjects/storage)

Ably recovers short LiveObjects interruptions by replaying operations and longer
interruptions by resynchronizing current object state. For long-term archives or
collaborative text, you still need the corresponding storage policy and editing
model. [Ably recovery](https://ably.com/docs/products/liveobjects/recovery)

## How do they support AI features? [#how-do-they-support-ai-features]

Ably AI Transport provides durable sessions for agent conversations, including
streaming responses, reconnection, and access across devices. It can also use
LiveObjects for shared session state. Liveblocks Sync lets server-side code edit
shared documents alongside users. A resumable agent conversation and edits to a
shared document have different requirements. An application can need both.
[Ably AI Transport](https://ably.com/docs/products/ai-transport) ·
[Liveblocks server-side editing](/docs/products/sync/server-side-editing)

## How do the billing units compare? [#how-do-the-billing-units-compare]

For LiveObjects, Ably counts inbound operations, outbound deliveries, object
synchronization, connections, and channels under the applicable pricing model. A
map set counts as one inbound message; delivering that update counts once per
connected client. [LiveObjects billing](https://ably.com/docs/pricing/liveobjects)

For example, 100 map-set operations delivered to three connected clients produce
100 inbound and 300 outbound messages. That excludes initial object sync, other
operations, connection minutes, and channel charges. It is a usage illustration,
not an invoice estimate.

Liveblocks meters collaboration time, data updates, storage, and selected
collaboration features. Those units do not translate one-for-one into Ably
message counts. Use the same editing session and feature scope when estimating
either design. [Liveblocks pricing](/docs/pricing/plans)
