Choosing a realtime stack depends on what you are building. Some tools excel at
Postgres-backed app data, others at pub/sub messaging, and others at
collaborative documents with conflict resolution. Use the comparisons below to
match your requirements to the right option.

## Find the right comparison [#find-the-right-comparison]

| If you... | Start here |
| --- | --- |
| Use Postgres and want realtime app data alongside collaboration | [Liveblocks vs. Supabase](/docs/compare/liveblocks-vs-supabase) |
| Need a managed realtime messaging platform | [Liveblocks vs. Ably](/docs/compare/liveblocks-vs-ably) |
| Already have a collaboration stack around Yjs | [Liveblocks vs. Yjs](/docs/compare/liveblocks-vs-yjs) |
| Prefer a custom event-based WebSocket layer | [Liveblocks vs. Socket.IO](/docs/compare/liveblocks-vs-socketio) |
| Want a managed service for a collaborative editor | [Liveblocks vs. Tiptap Cloud](/docs/compare/liveblocks-vs-tiptap-cloud) |
| Are considering using AI to build your own collaboration | [Build vs. buy](/docs/compare/liveblocks-vs-building-with-ai) |

Liveblocks is a hosted sync engine for collaborative applications. It provides
[Storage](/docs/products/sync/storage), [Presence](/docs/products/sync/presence),
[Comments](/docs/products/comments), [Notifications](/docs/products/notifications),
[version history](/docs/products/sync/version-history), and
[editor integrations](/docs/products/sync/integrations) so you can ship
multiplayer features without running your own realtime infrastructure. Learn more
in [Explore Sync](/docs/products/sync).
