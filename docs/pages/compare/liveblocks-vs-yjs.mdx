Liveblocks is a realtime collaboration platform that allows you to build
multiplayer applications where users and agents can work together. It provides a
sync engine that powers shared documents, text editing, presence, and more. Yjs
is an open-source CRDT library that merges concurrent edits to shared maps,
arrays, and text, with bindings for many editors and a choice of network
providers.

## Which should you choose? [#which-should-you-choose]

This is not an either/or choice. Yjs is a library that merges edits inside a
document; it does not connect people, store the document, or check who can open
it. Liveblocks is a platform that does those things, and it
[provides Yjs](/docs/products/sync/text-editing/yjs) as one of its document
models: `@liveblocks/yjs` is a Yjs provider, and the Tiptap, BlockNote, and
Lexical integrations run on Yjs underneath. Liveblocks also has its own CRDT,
Storage with `LiveText`, for when you don't want a `Y.Doc` at all.

The real decision is where your Yjs document lives. Choose Liveblocks when you
want a working collaborative editor or board without running a provider,
persistence, and auth yourself: a team editing the same proposal with comments
in the margin, or a canvas where text sits inside shapes next to positions and
colors. Choose Yjs on your own provider when you already run one you are happy
with, or when you need something only that setup offers, such as peer-to-peer
sync over WebRTC. Either way you keep Yjs and your editor binding; see
[alternative or provider?](#is-liveblocks-an-alternative-to-yjs-or-a-yjs-provider)
for how the pieces fit.

## Is Liveblocks an alternative to Yjs or a Yjs provider? [#is-liveblocks-an-alternative-to-yjs-or-a-yjs-provider]

Both. [Liveblocks Yjs](/docs/products/sync/text-editing/yjs) is a provider for a
`Y.Doc`: Yjs defines the shared data, the provider connects people, and
Liveblocks stores the document. You keep Yjs and your editor binding, and use
Liveblocks for hosting, authentication, comments, and notifications. Liveblocks
[Storage](/docs/products/sync/storage) with
[LiveText](/docs/products/sync/storage#LiveText) is the alternative: a separate
CRDT document store that does not use Yjs at all.

For a code editor with Yjs, the pieces are: editor binding → `Y.Doc` →
Liveblocks Yjs provider → room. Your own authentication decides who can open the
room. Both the `Y.Doc` and any Storage data live in the same room, so you can
mix them.

Which to pick for a given document is covered in the
[LiveText vs Yjs](/docs/guides/livetext-vs-yjs) guide.

## Keep Yjs or move to LiveText? [#keep-yjs-or-move-to-livetext]

Keep Yjs if your editor already uses it. Adding Liveblocks does not require
converting the document to `LiveText`; connect the existing `Y.Doc` through the
supported integration and check the migration path before changing formats.

For a new canvas with text inside shapes, `LiveText` keeps the text in the same
Storage tree as the surrounding structured data, so positions, properties, and
words share one document, one history, and one snapshot. For a long-form editor,
or a binding that depends on the Yjs ecosystem, Yjs is the better fit. The
[LiveText vs Yjs](/docs/guides/livetext-vs-yjs) guide covers limits and editor
support in detail.

## What does a production Yjs editor need? [#what-does-a-production-yjs-editor-need]

A provider, somewhere to store the document, a way to authorize access, and a
plan for backup, export, and deletion. Yjs itself covers none of these. The
[Yjs ecosystem](https://docs.yjs.dev/ecosystem) includes several providers,
including hosted services, so running your own server is optional.

For a specification editor, the responsibilities split like this:

| Responsibility          | Yjs on its own                                | With Liveblocks as the provider                                                                                                                                                                                                                                                         |
| ----------------------- | --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Editor content          | `Y.Doc` and the editor binding.               | The same `Y.Doc` and binding.                                                                                                                                                                                                                                                           |
| Hosting and persistence | A provider you pick, plus a database adapter. | The Liveblocks room. Documents are stored automatically.                                                                                                                                                                                                                                |
| Authorization           | Business rules wired into your provider.      | Business rules in your server, which issues room access tokens. <InfoTooltip>Your server checks the user against your own auth, then issues a token for the room. <a href="/docs/api-reference/authentication" className="font-medium text-product-brand">Learn more.</a></InfoTooltip> |
| Review workflow         | Pick commenting and notification services.    | Liveblocks Comments and Notifications in the same room.                                                                                                                                                                                                                                 |

Switching provider does not change the document format. Permissions, history,
and comments from a previous service still need their own migration, because
they are specific to that service. See the list of
[integrations](/docs/products/sync/integrations) and the
[authentication](/docs/api-reference/authentication) reference.

## Pricing and deployment [#pricing-and-deployment]

[Yjs](https://docs.yjs.dev/) is free and open source, so the library itself
costs nothing. The cost is in what runs around it: a provider server, a database
for stored documents, authentication in front of the connection, comments and
notifications if you need them, and the time spent keeping all of that running.
Compare that complete stack with the [Liveblocks plan](/docs/pricing/plans) and
usage your editor needs.

A Yjs provider such as
[y-websocket](https://docs.yjs.dev/ecosystem/connection-provider/y-websocket)
runs on your own servers. Liveblocks offers
[self-hosting](/docs/platform/data-storage#Self-hosting) as a paid add-on on the
Enterprise plan. Either way, your own servers, database, backups, and operations
are part of the budget.
