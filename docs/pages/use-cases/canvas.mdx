Collaborative canvases combine persistent objects with temporary user state. Use
Storage for shapes and layers, Presence for cursors and selections, multiplayer
history for undo/redo, and Comments for annotations.

<Banner title="Build a collaborative canvas" type="info">

Start with the [Tldraw and Next.js guide](/docs/get-started/nextjs-tldraw), or
use the Sync APIs below with your own canvas renderer.

</Banner>

## APIs you need [#apis]

- [`LiveMap`](/docs/api-reference/liveblocks-client#LiveMap) for shapes keyed by
  stable IDs
- [`useStorage`](/docs/api-reference/liveblocks-react#useStorage) and
  [`useMutation`](/docs/api-reference/liveblocks-react#useMutation) for shared
  shape state
- [`useOthers`](/docs/api-reference/liveblocks-react#useOthers) and
  [`useUpdateMyPresence`](/docs/api-reference/liveblocks-react#useUpdateMyPresence)
  for cursors and selections
- [`useUndo`](/docs/api-reference/liveblocks-react#useUndo) and
  [`useRedo`](/docs/api-reference/liveblocks-react#useRedo) for multiplayer
  history
- [Comments](/docs/products/comments) for anchored discussions

```tsx
const shapes = useStorage((root) => root.shapes);

const moveShape = useMutation(
  ({ storage }, id: string, x: number, y: number) => {
    storage.get("shapes").get(id)?.update({ x, y });
  },
  []
);
```

Group the mutations generated by one drag gesture into one history entry. Keep
pointer coordinates and current selections in Presence rather than Storage.

## Design the document [#design-the-document]

Represent independently edited objects as separate `LiveObject` values inside a
`LiveMap`. Use a `LiveList` only when shared ordering is significant, such as a
layer stack. Read [Data types](/docs/products/sync/data-types) and
[Conflict resolution](/docs/products/sync/conflict-resolution) before choosing
the shape.
