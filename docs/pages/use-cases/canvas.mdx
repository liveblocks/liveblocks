Create a collaborative canvas, whiteboard, or design tool with Liveblocks. Start
with a ready-made canvas, or create something custom. Add draggable objects,
show live cursors, upload images, use version history, and add multiplayer
undo/redo.

## Features [#features]

- [**Realtime collaboration**](#realtime-collaboration): Canvas state is
  permanent and updates in realtime for connected users.
- [**Presence**](#presence): Show live cursors, avatar stacks, realtime
  selections, and agent activity.
- [**Agentic editing**](#agentic-editing): Create AI agents that can modify the
  canvas from the back-end.
- [**Version history**](#version-history): Save, preview, and restore canvas
  state from snapshots.
- [**Multiplayer undo/redo**](#multiplayer-undo-redo): Each user can
  independently undo and redo their own changes.
- [**File uploads**](#file-uploads): Upload images and other assets with
  `LiveFile`, then add them to the shared canvas.
- [**Comments**](#comments): Add draggable commenting threads to the canvas.
- [**Permissions**](#permissions): Control which users can read and edit the
  canvas.

## Implementation [#implementation]

This is an overview of how each feature can be implemented. Note that if there’s
already an integration or ready-made component, this feature may work out of the
box.

Store persistent objects, layer order, and
[`LiveFile`](/docs/api-reference/liveblocks-client#LiveFile) references in Sync.
Keep temporary cursors, selections, and active tools in
[Presence](/docs/products/sync/presence), and use
[Comments](/docs/products/comments) for discussions attached to canvas
coordinates or objects.

### Realtime collaboration [#realtime-collaboration]

Store canvas objects in a
[`LiveMap`](/docs/api-reference/liveblocks-client#LiveMap), keyed by stable IDs,
and model each object with a
[`LiveObject`](/docs/api-reference/liveblocks-client#LiveObject). Keep shared
layer order in a [`LiveList`](/docs/api-reference/liveblocks-client#LiveList).
Read only the data a component renders with
[`useStorage`](/docs/api-reference/liveblocks-react#useStorage), then update it
inside [`useMutation`](/docs/api-reference/liveblocks-react#useMutation).
Mutations are applied optimistically and synchronized through Sync, including
every position update while a shape is dragged.

```tsx
import { useMutation, useStorage } from "@liveblocks/react/suspense";

function Shape({ id }: { id: string }) {
  const shape = useStorage((root) => root.shapes.get(id));
  const moveShape = useMutation(
    ({ storage }, x: number, y: number) => {
      storage.get("shapes").get(id)?.update({ x, y });
    },
    [id]
  );

  if (!shape) return null;

  return <CanvasShape {...shape} onMove={moveShape} />;
}
```

Read [Data types](/docs/products/sync/data-types) to choose the canvas document
shape and [Conflict resolution](/docs/products/sync/conflict-resolution) to
understand how concurrent changes are merged. Canvas interactions can update
many times per second, so select only the Storage data each component renders.
For smoother remote motion, set the
[`throttle`](/docs/api-reference/liveblocks-react#LiveblocksProviderThrottle) on
`LiveblocksProvider` to `16`. Lower values send updates more frequently, making
focused selectors especially important.

### Presence [#presence]

Keep cursors, selections, active tools, and agent activity in
[Presence](/docs/products/sync/presence), because this state is temporary and
should disappear when a connection ends. Publish the current user’s state with
[`useUpdateMyPresence`](/docs/api-reference/liveblocks-react#useUpdateMyPresence)
and subscribe to only the fields you render with
[`useOthersMapped`](/docs/api-reference/liveblocks-react#useOthersMapped). Store
cursor positions in canvas coordinates so they remain attached to the same point
as users pan and zoom. Convert screen coordinates to canvas coordinates before
updating Presence, then apply the current viewport transform when rendering
other users’ cursors.

```tsx
import {
  shallow,
  useOthersMapped,
  useUpdateMyPresence,
} from "@liveblocks/react/suspense";

function CanvasPresence() {
  const others = useOthersMapped(
    (other) => ({
      cursor: other.presence.cursor,
      selectedShapeId: other.presence.selectedShapeId,
    }),
    shallow
  );
  const updateMyPresence = useUpdateMyPresence();

  return (
    <PresenceLayer
      others={others}
      onPointerMove={(cursor) => updateMyPresence({ cursor })}
    />
  );
}
```

### Agentic editing [#agentic-editing]

AI agents and other trusted server processes can edit the same canvas with
[`Liveblocks.mutateStorage`](/docs/api-reference/liveblocks-node#mutate-storage).
The mutation uses the same Storage data types as the client, and connected users
receive the result in realtime. Run agent mutations on your backend, validate
the generated values, and create a version before applying a broad change.

```ts
await liveblocks.mutateStorage("canvas-room", ({ root }) => {
  root.get("shapes").get(shapeId)?.update({
    x: suggestedPosition.x,
    y: suggestedPosition.y,
  });
});
```

Read [Agentic editing](/docs/products/sync/agentic-editing) for validation,
server Presence, JSON Patch, and multi-step agent workflows.

### Version history [#version-history]

Create a version when a user publishes the canvas, before importing data, or
before an AI agent makes a substantial edit. Use
[`useHistoryVersions`](/docs/api-reference/liveblocks-react#useHistoryVersions)
to list versions,
[`useHistoryVersionStorageData`](/docs/api-reference/liveblocks-react#useHistoryVersionStorageData)
to render a read-only preview, and
[`useRestoreToStorageVersion`](/docs/api-reference/liveblocks-react#useRestoreToStorageVersion)
to restore the complete canvas Storage state as one synchronized change.

```tsx
import { useRestoreToStorageVersion } from "@liveblocks/react";

function RestoreCanvas({ versionId }: { versionId: string }) {
  const restore = useRestoreToStorageVersion(versionId);

  return <button onClick={() => restore()}>Restore this canvas version</button>;
}
```

Automatic versions can be enabled in the dashboard, and meaningful snapshots can
be created from a backend with
[`Liveblocks.createVersionHistorySnapshot`](/docs/api-reference/liveblocks-node#create-version-history-snapshot).
Read [Version history](/docs/products/sync/version-history) for the complete
preview and restore flow.

### Multiplayer undo/redo [#multiplayer-undo-redo]

Use [`useHistory`](/docs/api-reference/liveblocks-react#useHistory) to give each
user an independent undo and redo stack. Pause history at the start of a drag
and resume it at the end: every position still synchronizes, but the complete
gesture becomes one undo step without reversing another user’s work.

```tsx
import { useHistory } from "@liveblocks/react/suspense";

function CanvasHistory() {
  const { undo, redo, pause, resume } = useHistory();

  return (
    <Canvas
      onUndo={undo}
      onRedo={redo}
      onDragStart={pause}
      onDragEnd={resume}
    />
  );
}
```

Use [`useCanUndo`](/docs/api-reference/liveblocks-react#useCanUndo) and
[`useCanRedo`](/docs/api-reference/liveblocks-react#useCanRedo) to disable
unavailable controls. Read
[Multiplayer undo/redo](/docs/products/sync/multiplayer-undo-redo) for keyboard
shortcuts and the non-React client API.

### File uploads [#file-uploads]

Upload images, videos, and other binary assets with
[`useUploadFile`](/docs/api-reference/liveblocks-react#useUploadFile). It
uploads the file to the current room and returns an immutable
[`LiveFile`](/docs/api-reference/liveblocks-client#LiveFile) reference. Store
that reference on a canvas object so it synchronizes with the rest of the
canvas, then resolve it to a temporary URL with
[`useFileUrl`](/docs/api-reference/liveblocks-react#useFileUrl) when rendering.

```tsx
import { LiveObject, type LiveFileData } from "@liveblocks/client";
import {
  useFileUrl,
  useMutation,
  useUploadFile,
} from "@liveblocks/react/suspense";

function UploadImageButton() {
  const uploadFile = useUploadFile();
  const insertImage = useMutation(
    async ({ storage }, id: string, file: File) => {
      const liveFile = await uploadFile(file);

      storage.get("shapes").set(
        id,
        new LiveObject({
          type: "image",
          x: 0,
          y: 0,
          file: liveFile,
        })
      );
    },
    [uploadFile]
  );

  return <FilePicker onSelect={(id, file) => insertImage(id, file)} />;
}

function CanvasImage({ file }: { file: LiveFileData }) {
  const { url } = useFileUrl(file);

  return url ? <img src={url} alt={file.name} /> : null;
}
```

Do not put binary data directly in `LiveObject`, `LiveMap`, or `LiveList`. Read
about [LiveFile](/docs/products/sync/data-types#livefile) and check the
[file upload limits](/docs/pricing/limits). The Advanced Collaborative
Whiteboard example below implements image uploads with this pattern.

### Comments [#comments]

Attach [Comments](/docs/products/comments) to canvas coordinates or object IDs
with thread metadata. A
[`FloatingComposer`](/docs/api-reference/liveblocks-react-ui#FloatingComposer)
can create a thread at the selected point, while
[`useThreads`](/docs/api-reference/liveblocks-react#useThreads) renders existing
threads and
[`useEditThreadMetadata`](/docs/api-reference/liveblocks-react#useEditThreadMetadata)
saves a new position after a thread is dragged. Store thread positions in canvas
coordinates, then apply the same viewport transform used by shapes and cursors
when rendering them. This keeps threads attached to the correct location while
the canvas is panned or zoomed.

```tsx
import { CommentPin, FloatingComposer } from "@liveblocks/react-ui";

function CommentAtPoint({ x, y }: { x: number; y: number }) {
  return (
    <FloatingComposer metadata={{ x, y }}>
      <CommentPin
        style={{ position: "absolute", transform: `translate(${x}px, ${y}px)` }}
      />
    </FloatingComposer>
  );
}
```

Follow the
[draggable canvas Comments quickstart](/docs/get-started/nextjs-comments-canvas)
for placement mode, z-index management, and draggable thread components.

### Permissions [#permissions]

Create a room for each canvas and set its access from your backend with
[`Liveblocks.createRoom`](/docs/api-reference/liveblocks-node#post-rooms). Give
editors `*:write`, viewers `*:read`, and keep `defaultAccesses` empty for a
private canvas. These room permissions control the canvas Storage, Presence,
Comments, and other resources available to each authenticated user.

```ts
await liveblocks.createRoom(`canvas:${canvasId}`, {
  defaultAccesses: [],
  groupsAccesses: {
    [editorsGroupId]: ["*:write"],
    [viewersGroupId]: ["*:read"],
  },
});
```

Issue ID tokens from an [authentication endpoint](/docs/authentication) and read
[Permissions](/docs/authentication/permissions) for user, group, and room access
patterns. Trusted server APIs use a secret key, so validate the requesting user
in your own backend before editing on their behalf.

## Production considerations [#production-considerations]

Use
[`useLostConnectionListener`](/docs/api-reference/liveblocks-react#useLostConnectionListener)
to tell users when the canvas is taking longer than expected to reconnect. Sync
continues to apply local changes optimistically while reconnecting and catches
the client up when the connection returns.

Enable
[`preventUnsavedChanges`](/docs/api-reference/liveblocks-react#prevent-users-losing-unsaved-changes)
on `LiveblocksProvider` to warn users who close the page before their latest
canvas changes have synchronized.
