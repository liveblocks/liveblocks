Tables, data grids, and spreadsheets can synchronize records and cells, show
live selections, and attach comments to rows or cells. Choose Sync when users
edit shared data and Comments when the data already lives in your database but
needs discussion.

## Synchronize records and cells [#sync]

- [`LiveMap`](/docs/api-reference/liveblocks-client#LiveMap) for records or
  sparse cells keyed by stable IDs
- [`LiveList`](/docs/api-reference/liveblocks-client#LiveList) for dense,
  ordered rows
- [`useStorage`](/docs/api-reference/liveblocks-react#useStorage) and
  [`useMutation`](/docs/api-reference/liveblocks-react#useMutation) for shared
  values
- [`useUpdateMyPresence`](/docs/api-reference/liveblocks-react#useUpdateMyPresence)
  for temporary selections and active-cell state
- [Multiplayer undo/redo](/docs/products/sync/multiplayer-undo-redo) for shared
  edit history

```tsx
const grid = useStorage((root) => root.grid);

const setCell = useMutation(
  ({ storage }, row: number, column: number, value: string) => {
    storage.get("grid").get(row)?.set(column, value);
  },
  []
);
```

For sparse or very large tables, use stable IDs and maps rather than allocating
every empty cell. Batch multi-cell edits so paste and fill operations create one
history entry.

## Add contextual comments [#comments]

- [`useThreads`](/docs/api-reference/liveblocks-react#useThreads) for comments
  filtered by row or cell metadata
- [`FloatingThread`](/docs/api-reference/liveblocks-react-ui#FloatingThread) and
  [`FloatingComposer`](/docs/api-reference/liveblocks-react-ui#FloatingComposer)
  for contextual comment UI

```ts file="liveblocks.config.ts"
declare global {
  interface Liveblocks {
    ThreadMetadata: {
      rowId: string;
      columnId?: string;
    };
  }
}
```

Use stable record and column IDs in thread metadata so comments remain attached
after sorting or filtering.

## Keep server data canonical [#server-data]

If the canonical records live in your database, keep them there and use
[Broadcast events](/docs/products/sync/broadcast-events) to tell other clients
when to revalidate with SWR or another data-fetching library.
